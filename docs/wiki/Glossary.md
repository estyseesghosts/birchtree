# Glossary

Every term a newcomer needs for birchtree / Mastodon v4.7.3 interop.

- **Account vs user (local credential):** `Account` is the ActivityPub identity + client-visible profile (handle, domain, actor URI, inbox/sharedInbox, fields, avatar/header, flags, move target). `LocalUser` is the login + preferences record (Argon2 password hash, email, disabled flag, default privacy/sensitive/language/quote policy, mention policy, chosen languages, roles `Admin/Moderator/None`). Never conflate them; OAuth records are a third thing. Bootstrap the first admin/account by CLI.
- **Actor:** the ActivityPub `Person` document for an account (`{id, preferredUsername, name?, summary?, inbox, endpoints.sharedInbox, publicKey, followers, following, outbox, alsoKnownAs:None, featuredTags, icon?, image?}`). Keys: RSA-2048, `keyId={actor}#main-key`; instance actor id `0`.
- **Visibility:** `public` (fetchable + distributable), `unlisted` (fetchable, excluded from public distribution), `private` (follower/mentioned-targeted), `direct` (mentioned-targeted; never leaks via public/list/search/stream/federation). **Limited** is upstream's fifth internal state; birchtree has no `Limited` variant — it projects to `private` in REST but has no runtime rule yet (open). `distributable = public|unlisted`; reblogs exclude direct/limited.
- **Reblog vs quote:** a reblog (boost/announce) is a separate status row pointing at the original, no new text. A quote embeds another status with its own state machine (`pending | accepted | rejected | revoked | deleted`) + quote/approval URIs, separate counts, safe previews that never leak protected targets. REST: `quoted_status_id` + `quote_approval_policy` on create, `quote`/`quote_approval`/`quotes_count` on read, list/revoke endpoints, `PUT …/interaction_policy`.
- **Quote policies / states:** `QuotePolicy::{Public, Followers, Nobody}`; private/direct quoted content forces `Nobody` and escalates the wrapper. Remote flow is FEP-044f `QuoteRequest → Accept/Reject` (+ `Delete{QuoteAuthorization}` revoke); `Accept` needs a `result` auth URI. Quotability ≠ visibility (`quote_permission → Self|Automatic|Denied`).
- **Interaction policy:** per-action predicates, not one boolean: `can_fetch` (show), `can_fetch_full` (+mute/domain; reads use the former, interactions the latter — known inconsistency, matrix test open), `can_reblog / can_favourite / can_bookmark`, `quote_permission`, `is_owner` (edit/delete). Stricter-than-upstream trio (registered): viewer-blocks-author denies fetch, viewer-mutes-author denies, bookmark denies on viewer-block.
- **Idempotency:** `POST /api/v1/statuses` honors `Idempotency-Key` per account, 1h TTL; replays return the original status, no duplicate outbox/job.
- **Dedup vs tombstone:** ingress dedups by canonical activity URI (`ACTIVITY_DEDUP`, 7-day TTL) but records applied-only (`Duplicate|Applied`, never `Ignored` — D33, because Mastodon reuses Undo IDs). **Tombstones** are terminal delete markers that beat late Creates in both directions (served as `Tombstone` 410; batch 50/job).
- **Shared inbox:** `POST /inbox` receives for all local actors (one delivery instead of N); `POST /users/:username/inbox` is per-account. Egress dedups per distinct inbox. Relay fan-out reuses the same path but only for public content events.
- **Authorized fetch:** when `--federation-authorized-fetch` is on, note / quote-auth / collection reads require a valid HTTP signature (missing/invalid → 401).
- **WebFinger / NodeInfo:** `acct:` lookup → `application/jrd+json` (suspended → 410); live remote resolve on authed `lookup` with `resolve=true`. NodeInfo 2.0 serves real usage + `openRegistrations` + node metadata; `software.name` is `birchtree` (D48).
- **Outbox / collections:** `outbox` (base + cursor pages, 20/page, public only), `followers`/`following` (base + `?page=N`, 12/page cap 1000), `featured`/`featuredTags`, `replies` on every Note, `quote_authorizations/:id`, top-level `collections` CRUD + `items` + `revoke` with `hide_collections` enforced everywhere.
- **Fan-out-on-read vs materialized:** birchtree does bounded fan-out-on-read (k-way merge over followed-author ranges, home cap 1000, no Redis); a durable rebuildable `redb` feed index is the documented fallback if Phase-8 benchmarks demand it — derived state only, never authoritative. No `206` home regeneration (D9).
- **SSE vs WS:** two transports, one hub. SSE (`GET /api/v1/streaming/:channel`, `event:/data:` frames, `:thump` 15s) and WebSocket (any path under `/api/v1/streaming`, `?stream=` + subscribe frames, ping 30s, double-encoded `{stream,event,payload}`). Channels: `user (+notifications iff scoped), user:notification, public (+local/remote/media), hashtag (+local), list, direct`. Events: `update, status.update, delete, notification, conversation` (**`direct` carries only `conversation`**, D18), `announcement(.reaction/.delete)` on `user`, `notifications_merged "1"`. Nothing persisted/replayed. Bounds D14 apply.
- **Markers:** saved read positions per timeline (`GET/POST /api/v1/markers`, `home` + `notifications`, `lock_version` → 409 on conflict).
- **Filters vs mutes vs blocks:** **filters** = keyword/status rules (`hide|warn`), v1 + v2, applied as `filtered` annotations at render. **Mutes** = per-account silence (+expiry, notification variant). **Blocks** = two-way sever (both directions deny fetch; creation-time notification drops D26; retroactive rows kept). Domain blocks are local-only; only blocks sever endorsements today (no sever cascade).
- **Scheduled statuses:** `scheduled_at` on create (past → posts now; <5 min → 422; caps 300 total / 25 per UTC day) + index/show/update/destroy + durable `PublishScheduledStatus` job. Scheduled **announcements** stay drafts until manually published (no job).
- **Collections:** top-level named sets (CRUD + `items` + `revoke`, `in_collections`, per-account lists, minimal `v1_alpha`) with `added_to_collection` / `collection_update` notifications; non-owners read `[]` (`hide_collections`, D52).
- **Announcements:** admin-authored (API authoring, no HTML authoring, no schedule job), list/dismiss/react + `announcement*` stream events on `user` streams.
- **Trends:** admin-approved tags/links/statuses ranked by observed-usage score with day-scale decay (decided D40 constants, no Redis/threshold); link cards crawled via the safe client (200 KiB, null until landed); tag history = seven real per-day buckets; `?locale=` orders-first on statuses, inert on tags/links. Approved non-public statuses hide from unauthorized viewers (D41).
- **Reports / Flag:** `POST /api/v1/reports` (moderator queue) + server rules (CLI-managed, translated) + forwarding as ActivityPub `Flag{object=[target, …statuses], content}`.
- **VAPID / push:** Web Push subscriptions (scope `push`) + VAPID-keyed delivery as a post-commit job (RFC 8291 `aes128gcm` + draft-04 `aesgcm` legacy, keyless legacy tickle only; empty `access_token`/`icon` never fabricated, D42). Needs configured VAPID keys.
- **FEP-044f:** the quote-authorization protocol birchtree implements (`quote` + `quoteAuthorization` + `quoteUri`/`_misskey_quote` inbound; emits `quote` + `quoteAuthorization` only — no `quoteUri` dup, `RE:` fallback, or `interactionPolicy`; known interop delta).
- **D-codes:** rows in the deviation register (`docs/compatibility-profile.md`) — the only legal differences from v4.7.3. A client-visible difference not in the register is a bug. Headliners: D1–D4 WebM/VP9+WebP never-`gifv`; D5 ancestor completion; D6 search default-on; D8/D9/D13/D16/D17 timeline/streaming wire; D10 home 1000 + exclusive lists; D11 JSON bodies; D14 streaming bounds; D18/D19 direct-conversation / remote-public; D21–D26 language/mention/notification policy; D27–D29/D32–D34 federation; D35 admin flags; D36–D41 queues/trends/metrics; D42 push; D43 conversation-id=root; D44 CSRF; D45–D47 stricter privacy; D48 rebrand; D49–D52 delivery/cursor/notifier/`hide_collections`.

# Administration

Admin surface: roles + CLI, server config, JSON schema, the full admin API, what is enforced vs stored-only, deliberate Mastodon divergences, and an operator runbook.

## 1. Roles, scopes, auth errors

Three roles (`src/domain/user.rs`): `None` (default, id `0`, name `User`, perms `0`), `Moderator` (id `1`, upstream `view_dashboard|view_audit_log|view_feeds|manage_users|manage_reports|manage_taxonomies` = `1049884`), `Admin` (id `2`, every upstream flag). Bit positions are the single canonical copy (`PERM_*` matching `app/models/user_role.rb`); `-1` was upstream's `NOBODY_POSITION` sentinel, never a role id. All staff provisioning is CLI-only (`create-account --role=`, `grant-role --username= --role=admin|moderator|none`); no web UI, no REST grant endpoint.

Scopes (`src/api/oauth/scopes.rs`): `admin:read|write` + per-resource `admin:read|write:{accounts,reports,domain_allows,domain_blocks,ip_blocks,email_domain_blocks,canonical_email_blocks}`. Trends/tags/measures/dimensions/retention use bare `admin:read|write` (no sub-scopes upstream). Reads: accounts/reports accept moderator or admin; everything else admin-only (measures/dimensions/retention admit moderators via `require_metrics`). Writes follow the same split; account routes use fine-grained `require_admin_action` (D35: `ViewAccounts|ModerateAccount`, `ReviewReports`, `ManageDomainBlocks|IpBlocks|EmailBlocks|Tags`, `ViewMetrics`, `ManageAnnouncements`) checked against the bitmask **before** the scope check.

Order: `require_user` (app-only → 422; pending-approval → 403) → role (no role → `403 Forbidden`) → scope (missing → `403 outside the authorized scopes`). Every admin write appends one audit record.

## 2. Server config

Precedence: compiled defaults → `--config=PATH` JSON file → CLI flags. `validate()` + `check_runtime_mode()` run once; any error names the key and exits. Unknown keys rejected. Minimal file at `config.example.json`.

Selected keys: identity (`public_url` http(s), `data_dir` holds `birchtree.redb` + media dirs, `listen` default `0.0.0.0:3000`); proxies (`trusted_proxies[]`, rightmost-untrusted rule; untrusted `X-Forwarded-For` ignored); site (title/description/contact + `site_terms/privacy/extended_file`, null = honest 404); streaming (`streaming_api_base_url`, null = serve in-process); media caps (`max_file_size`/`max_body_size` 16 MiB defaults with `≤` enforced, `max_status_chars` 1–3000 default 500); search (`search_mode=embedded|database|off`, default embedded, restart to change); transcoding (`transcoding_enabled`, `ffmpeg_path`, `webp_quality` 0–100, `vp9_crf` 0–63, `vp9_cpu_used` 0–5, `opus_bitrate_kbps`, wall/output/memory caps — missing/non-working ffmpeg with transcoding on = startup error); federation (`federation_allow_http`, `federation_allowlist[]`, `federation_extra_ca`, `federation_authorized_fetch`, `relay_inboxes[]`, `federation_allow_private`); registration (`registration_open` default false, `registration_requires_approval`, `minimum_age_years` 13–21 default 16, `invites_enabled`); push/VAPID (`vapid_public/private_key`, `env:` indirection); mail (`smtp_url` smtp/smtps, `mail_from` — half-configured = startup error, unconfigured = explicit 503); keyring (`secret_keyring_file/env`, mutually exclusive, `0600`, first key seals / rest open; production refuses without one); feeds (`local|remote_live_feed_access`, `local|remote_topic_feed_access`, `peers/activity_api_enabled`, `domain_blocks_public` default false, `trends_enabled`); storage (`durable_dir` → `<data_dir>/media`, `cache_dir` → `<data_dir>/media_cache`, must be disjoint; `remote_cache{mode, caps, retention, warming}`); misc (`mode`, `unsafe_production_override` exact phrase, `worker_poll_interval_ms`, `password_reset_ttl_hours` 1–72, `web_client_dir` null = `/app/*` 404s, `rate_limit_multiplier`). Production refuses weakened settings (`federation_allow_http`, allowlist, extra CA, multiplier > 1) unless `--lab` or the exact override phrase.

Health: `GET /health` (liveness), `GET /ready` (storage + probes, 2s deadline, `200 ready` / `503 not ready`, failing names logged not returned), `GET /metrics` (loopback-only Prometheus). Startup logs a secret-free summary (secrets as `configured` booleans, SMTP scheme+host only).

## 3. JSON schema

`docs/config-schema.json` (draft-07) pins every file key and is enforced by `tests/config_file.rs` — schema and `src/config.rs` drifting fails the test. `additionalProperties: false`, every key optional, units in bytes (TTLs in hours / ms where named). Groups: deployment, site/feeds, limits/media, search/transcode, federation, secrets/mail/push, misc. Example in the Client/Operations pages; the schema file is authoritative.

## 4. Moderation tools

All rows: user token + role; moderator-or-admin vs admin-only as noted; `Link` cursors (`limit` 100/200 on accounts+reports) except trends (`offset/limit` 10). Every write commits state + audit atomically.

**Accounts** (`admin_accounts.rs`): `GET /api/v1/admin/accounts`, `GET /api/v2/admin/accounts` (+ `role_ids` 0/1/2 filter), `GET :id`, `DELETE :id` (suspend + disable immediately, revoke tokens + close streams permanently (D24), then bounded restartable `AccountDeletionBatch` 50/page + federated actor `Delete` (D38)), `POST :id/enable|unsensitive|unsilence|unsuspend|approve|reject` (local-only; approve/reject pending-only, already-decided → 403; none restore killed tokens), `POST :account_id/action` (nested param; warning rows stored, never e-mailed; `disable`/`suspend` kill tokens). Login-IP telemetry: `ip` = latest password-login IP, `ips[]` newest-first (schema v15); API calls on tokens are not sign-ins so `active_users` runs lower than Mastodon's throttled touches.

**Reports** (`admin_reports.rs`, wired to `POST /api/v1/reports`): index, show (reporter/target/assigned/action-by + full status serialization for the moderator viewer, `rules:[{id,text}]`), update (rule_ids validated, unknown → 422), `assign_to_self`, `unassign`, `reopen`, `resolve` (feeds `resolved_reports`).

**Trends** (`admin_trends.rs` + public `trends.rs`): admin review queue (`tags|links|statuses` index + approve/reject, admin-only) over the same candidates public reads derive; public serves only approved items. Tags carry 7-day real history; links crawl via the safe client (200 KiB cap, null until landed); statuses score-order by reblogs+favourites with day decay, `?locale=` orders-first, and approved non-public statuses hide from unauthorized viewers (D41).

**Domain allows/blocks** (`admin_infra.rs`): index/show/create/update/destroy (+ audit). Enforced at federation ingress and egress (Phase 6); never federated (parity).

**Email-domain / IP / canonical-email blocks:** CRUD (+ `POST canonical_email_blocks/test` dry-run read). Email/canonical wait on email confirmation (stored-only today). IP `no_access` / `sign_up_block` enforced when the middleware is mounted (`ip_block_middleware` + `is_sign_up_blocked_for`, trusted-proxy client IP).

**Tags:** flags index/show/update (stays admin-only until the finer D35 split rolls out module by module).

**Measures / dimensions / retention:** all `POST` with a **read** scope (kept from upstream), moderators admitted. Measures: `new_users`, `opened/resolved_reports`, `active_users` (daily unique password-logins), `instance_*` (follows/followers/statuses/reports/accounts/media), `tag_*` (need `<key>[id]>`, else omitted), `interactions` (unified journal). Dimensions: `languages`, `sources`, `servers`, `space_usage` (media + measured redb `database` bytes), `instance_accounts`, `instance_languages`, `tag_servers`/`tag_languages`. Retention: day/month cohorts, active = sign-in **union** authored status. Refused keys stay absent with reasons, never zero-filled: `software_versions` (no census), `postgresql`/`redis`/`search` sub-entries, tag rows without resolvable id.

**Announcements:** public list/dismiss/reactions + admin authoring (new API surface; upstream authoring is HTML-only): `GET+POST /api/v1/admin/announcements`, `GET+PUT+PATCH+DELETE :id`, `POST :id/publish|unpublish`. `POST` publishes immediately unless `scheduled_at` is in the future; plain update never flips `published`; **no publish job** — scheduled rows publish on explicit `publish`.

**Annual reports:** `:id` is the year; user scopes (not admin): index/show/state + `POST :id/generate` (202, durable job) + `POST :id/read`.

**Rules, terms, privacy, extended:** operator CLI (`create-rule/delete-rule/list-rules`, `set-rule-translation/delete-rule-translation` with `{locale:{text,hint}}`); `GET /api/v1/instance/rules` serves them; reports attach `rule_ids[]` (unknown → 422); admin report `rules` render `[{id,text}]` (deleted ids skipped, D37). Terms/privacy/extended served from `site_*_file`; null = honest 404. Also live: `instance/peers` (+gate), `instance/activity` (+gate), `instance/domain_blocks` (only when `domain_blocks_public`), `translation_languages`, `languages`.

## 5. Stored-only vs enforced

Domain blocks: stored + **enforced** (federation both directions). Email/canonical blocks: stored, **waiting on confirmation**. IP blocks: stored, **enforced when wired** (middleware + sign-up check). Token kill (suspend/disable/delete/reject, disable/suspend actions): **permanent** — revoked tokens 401 everywhere + `TokenRevoked` closes streams; re-enable never restores. Account deletion batches: **worker-driven**, 50/batch, each tombstone commits its own federated `Delete`; rows stay tombstoned. Retraction batches: request-path, 500/batch × 64/author-set (Phase-8 load item). Remote tombstones: **Delete-beats-Create both directions**, same-host. Refused metrics: omitted with reasons. Announcements scheduling: manual only. Warning e-mails: never sent. Donation campaigns: always 404.

## 6. Where we differ from Mastodon

No HTML dashboard / web UI — API + CLI only (out of profile by decision). Collapsed roles with numeric ids (`0/1/2`) + real bitmask string (`1049884` moderator); `collection_limit: 0` (fabricated). Permanent token kill (D24). Approval queue: `reject` suspends + disables with token kill (D38 worker removes after); confirmation-gated setup never runs (Phase-2 email gap). Rules: deletions leave stale ids skipped at render; warnings stored, never e-mailed; translations via CLI (D37). Deletion: same-day suspend + 50/batch worker, each tombstone its own federated `Delete` (D38). Metrics: refusal-with-reason instead of zero-fill (`software_versions` absent, `space_usage` = media + measured redb bytes, retention = sign-in ∪ authorship, tag keys need ids) (D39). Trends: decided constants (observed-use score, day decay, no threshold, safe-client crawl, 7-day tag history, `?locale=` orders-first on statuses) (D40). Private-trend guard (D41, privacy-protective). Misc kept out: translate, v1 search, oembed, `v1_alpha`, email subscriptions, featured-tag suggestions.

## 7. Operator runbook

**Bootstrap:** write config (public_url, data_dir, mail or null, keyring, VAPID for push) → create keyring (`<id>:<64 hex>` per line, `0600`) → `serve` once (dirs + redb) → `create-account --username=admin --role=admin` (password via env) → OAuth authorize → verify with `verify_credentials` + `admin/accounts?limit=1`. **Roles:** `grant-role --username=bob --role=moderator|admin|none` (no restart; config/flag changes need restart). **Registration:** `--registration-closed` (default) / `--registration-open` / `+ --registration-require-approval` (pending queue: hidden from multi-fetch, 403 at login + user endpoints until `approve`; `reject` suspends + kills tokens). **Backups:** stop or snapshot; copy `birchtree.redb` + `media/` (+ `media_cache/` optional, refetchable); back up the keyring **separately** (losing every sealing key orphans MFA seeds, actor keys, outbox bearers — fail closed). Schema v21 with idempotent backfills; newer-than-code refused. **Restarts:** config loads once; watch the secret-free `startup_summary`; probe `/health` then `/ready`. **Logs:** `tracing` (`RUST_LOG`), request IDs, per-endpoint rate limits; secrets, tokens, codes, passwords, DM bodies, signatures, keys, seeds never logged; sign-ins record `(account, created_at_ms, ip)` for admin telemetry; every admin write appends an audit row.

## Refused keys (keep listed, with reason)
- `interactions` (measures): no unified interaction event log — posts, favourites, reblogs, votes and follows are not journaled as events / upstream `app/lib/admin/metrics/measure/interactions_measure.rb` (`ActivityTracker('activity:interactions')`). Constant: `REFUSED_INTERACTIONS` in `src/api/mastodon/endpoints/admin_infra.rs`.
- `software_versions` (dimensions): no component-version census is collected / upstream `app/lib/admin/metrics/dimension/software_versions_dimension.rb`. Constant: `REFUSED_SOFTWARE_VERSIONS` in `src/api/mastodon/endpoints/admin_infra.rs`.
- `tag_accounts`/`tag_uses`/`tag_servers` (measures) and `tag_servers`/`tag_languages` (dimensions) without a resolvable `<key>[id]>`: tag measures/dimensions need `<key>[id]>` naming a trend-flag or admin-tag row id (upstream `params.require(key).permit(:id)` → 400 when missing; we omit leniently) / upstream `tag_*_measure.rb` + `tag_*_dimension.rb` (`with_params?`). Constants: `REFUSED_TAG_NO_ID`, `REFUSED_TAG_UNKNOWN_ID`. With the id the keys are SERVED (not refused).
- `space_usage` sub-entries `postgresql`/`redis`/`search`: this server has no postgres/redis, and the embedded search index lives inside the same redb file already measured as `database` / upstream `space_usage_dimension.rb:12-75`.
